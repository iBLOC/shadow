# 客户端调用点 → 端脑路由 对照表（机器可读）
#
# 格式：<客户端文件> <METHOD> <客户端路径> <状态> <面> <服务端方法> <服务端路径>
#
#   客户端文件 —— 相对仓根
#   METHOD      —— 客户端用的方法
#   客户端路径  —— **归一化**后的路径（${…} ⇒ {param}，查询串去掉）
#   状态：
#     aligned —— 服务端**原样**有这条路径，方法也对得上 ⇒ 客户端今天就该能用
#     outer   —— 落在 outer 面（neuron 在根 / hippocampus nest 在 /hippocampus）
#                ⇒ 路径对得上，且**不在门后**（门只罩端脑自己那张面）
#     differs —— 服务端**有**这项能力，但路径或方法不同 ⇒ 需要迁移
#     missing —— 服务端**没有**这项能力 ⇒ 需要产品决定（不阻断，留在视野里）
#   面         —— telencephalon / hippocampus / neuron / none
#   服务端方法 —— 服务端那条路由的方法（- = 没有对应面）
#   服务端路径 —— 服务端那条路由的路径（- = 没有对应面）
#
# ⚠️ 本表由 scripts/check-client-endpoint-map.mjs 盯着：
#   客户端新增调用点而没登记 ⇒ 红；端脑改了路由而表没改 ⇒ 红；表里有过期行 ⇒ 红。
