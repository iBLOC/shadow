## Android InCallService 设计

`CallRoutingService.kt` 继承 `android.telecom.InCallService`:

```kotlin
class CallRoutingService : InCallService() {
    override fun onCallAdded(call: Call) {
        // Auto-answer if AI mode active
        if (call.state == Call.STATE_RINGING) call.answer(0)
    }
    override fun onCallStateChanged(call: Call, state: Int) {
        when (state) {
            CALL_ACTIVE -> routeAudioToUsb()
            CALL_DISCONNECTED -> restoreNormalAudioMode()
        }
    }
}
```

**Audio routing 核心:**
```kotlin
private fun routeAudioToUsb() {
    val am = audioManager
    am.mode = AudioManager.MODE_IN_CALL
    // Find shadow-esp32 USB device
    val usbDevice = am.getDevices(GET_DEVICES_OUTPUTS)
        .firstOrNull { it.productName.contains("shadow-esp32") }
    am.preferredDevice = usbDevice  // Android 12+ API
    am.isSpeakerphoneOn = false
}

// On earphone plug-in:
private fun routeAudioToEarphone() {
    val earphone = am.getDevices(GET_DEVICES_OUTPUTS)
        .firstOrNull { it.type == AudioDeviceInfo.TYPE_WIRED_HEADSET }
    am.preferredDevice = earphone
    am.isSpeakerphoneOn = false
}
```

**IN_CALL mode vs MODE_IN_COMMUNICATION:**
- `MODE_IN_CALL` — actual phone calls (requires system permission, some phones intercept)
- `MODE_IN_COMMUNICATION` — VoIP / call apps (less restricted, better for demo)
- v2.8 uses `MODE_IN_CALL` for real phone calls; some vendor ROMs may require `MODE_IN_COMMUNICATION` fallback

**BIND_INCALL_SERVICE requirement:**
- This is the most restrictive part — the app must be set as the **default phone app** on the phone to receive call events
- For demo, user can temporarily set shadow-mobile as default phone app
- For production: need a dedicated "shadow phone" component, or use a background service to intercept calls without InCallService

## 已知限制

1. **BIND_INCALL_SERVICE** — 需要用户把 shadow-mobile 设为默认电话 app(否则收不到 call events)
2. **MODE_IN_CALL vendor 差异** — 华为/小米等厂商可能拦截 `setPreferredDevice(USB)` 在 call mode 里的调用;需实测 fallback 到 `MODE_IN_COMMUNICATION`
3. **AudioRecord(VOICE_CALL)** — AI 捕获来电声音需要用 `AudioRecord(AUDIO_SOURCE_VOICE_CALL)`,部分厂商 DRM 拦截
4. **没有双向 audio 路由逻辑** — v2.8 routing service 只管 preferred device;真正"把 caller voice + AI TTS 都路由到 USB Audio"需要进一步 Android audio routing 逻辑
5. **TelephonyManager vs AudioManager** — `setPreferredDevice()` 是 AudioManager API,不是 TelephonyManager;两者路由逻辑不同
