# 闸的治理闸（scripts/check-gate-discipline.mjs）

> 2026-11-05 · iBLOC/shadow · 「**闸也必须守纪律**」

## 0. 一句话

本仓有 **35 道闸**（scripts/check-*.mjs）⇒ ⇒ 一盏绿的 CI 只能证明其中
**15 道**没问题 ⇒ ⇒ 而「有闸但没人跑」是最容易被忽略的那种缺口 ⇒ ⇒
所以：**闸本身也要被管**。

## 1. 病（2026-11-05 真机实测）

| 读数 | 值 |
|---|---|
| 闸总数 | 35（含本闸自己） |
| 接进 ci.yml | **15** |
| 没接进 CI（**有闸但没人跑**） | **20** |
| 自检印出可数读数（N/N） | **7** |
| 印不出可数读数 | **28** |
| **没有** --self-test | **7** |
| 自检退出码 2（本机判不了：cargo 工具链 / 兄弟仓在位） | **3** |
| 没有「退出码 2」这一档 | **10** |

⇒ ⇒ 病根不是「闸写得不好」，是「**没有一道闸在管闸**」⇒ ⇒ 而那 7 道没有
--self-test 的闸，传了 --self-test 也只是跑一次正常检查 ⇒ ⇒ **恒绿的自检**
（看着有自检，其实证明不了任何事）。

## 2. 五条纪律

| 编号 | 种类 | 抓什么 |
|---|---|---|
| D1 | no-self-test | 闸必须支持 --self-test |
| D2 | self-test-broken | 闸的 --self-test 必须绿（红 = 闸自己坏了） |
| D3 | no-reading-in-wired | 接进 CI 的闸，自检必须印出可数读数（N/N） |
| D4 | not-wired-into-ci | 闸必须接进 .github/workflows/ci.yml |
| D5 | no-cannot-judge-exit | 闸必须能以退出码 2 表达「判不了」 |

## 3. 两条设计决定（写清楚，免得后来人当成漏洞）

① **自检退出码 2 不判红**：那是「本机判不了」（环境缺），不是纪律违规 ⇒ ⇒
它被**显式打印**（⚠ 行）⇒ ⇒ 但不进退出码 ⇒ ⇒ 这样同一份债清单在**本机与
CI 两边都对得上**（不因环境漂移）。

② **行为类判据（D2 / D3）只对「CI 已经在跑的那些闸」生效** ⇒ ⇒ 行为类要
跑别的闸 ⇒ ⇒ 依赖环境 ⇒ ⇒ 若对全部 35 道都硬判 ⇒ ⇒ 本机与 CI 的结论会
不一致 ⇒ ⇒ 债清单就没法对账 ⇒ ⇒ `--scope` 只决定**量多少道**（工作量），
不决定**判多少条**。

## 4. 存量债的放行规则

历史闸大多不按今天的纪律写 ⇒ ⇒ 它们是**别的工作线**的、且多数需要本机
工具链 ⇒ ⇒ 登记在 scripts/lib/gate-discipline-registry.mjs：

- **登记在册** ⇒ ⇒ 放行（**但仍然打印** ⇒ ⇒ 放行 ≠ 看不见）；
- **没登记的新缺口** ⇒ ⇒ 直接红（不许悄悄长出来）；
- 登记了、但缺口已经不在 ⇒ ⇒ 红（**要销账** ⇒ ⇒ 清单不许过期）。

每条债都写清「为什么还没修」＋「什么时候修」。

## 5. 用法

    node scripts/check-gate-discipline.mjs                # 全量（本地）
    node scripts/check-gate-discipline.mjs --self-test    # 判据自检（13 条）
    node scripts/check-gate-discipline.mjs --audit        # 现状清单（每道闸一行）
    node scripts/check-gate-discipline.mjs --json         # 机器可读
    node scripts/check-gate-discipline.mjs --scope=wired  # 只量 CI 在跑的闸

退出码：**0 绿 / 1 红 / 2 判不了**（判不了 ≠ 没问题）。

## 6. CI 接线

接在 **cortex-residue-stack** job 里 ⇒ ⇒ 因为那个 job **已经把所有兄弟仓
检出到工作区** ⇒ ⇒ 那些要兄弟仓在位的闸（cortex-residue-all /
neuron-ownership）在这里才判得了 ⇒ ⇒ 放在只 checkout 了 shadow 的 job 里
⇒ ⇒ 它们只会「判不了」（绿灯但什么都没查）。

## 7. 它顺带逮到的三条真缺陷（2026-11-05）

① **cortex 残留闸是红的**（它已接 CI ⇒ ⇒ CI 除了计费之外还会红）：残留
   来自 state-surface 闸里一句注释的旧名 ⇒ ⇒ 改措辞 ⇒ ⇒ shadow / 桌面端 /
   移动端各 0 处；
② **端点矩阵过期**：端脑新增 `POST /models/providers/{id}/reveal` 没进矩阵
   ⇒ ⇒ 那道闸红了却**没人跑** ⇒ ⇒ 已补录（它是**只有 admin 能开**、回吐
   真实密钥的接口 ⇒ ⇒ 恰恰最该进这张表）；
③ **跨仓 cortex 闸因新仓 ziti-rust 未登记而阻断**（「有闸但漏了仓」比「没有
   闸」更危险）⇒ ⇒ 已登记进注册表，并显式写明 CI 还没检出它。

## 9. 边界

- **不判闸的逻辑对不对**：只判「它守不守纪律」⇒ ⇒ 判据质量仍要人看。
- **行为类只在 CI 在跑的那些闸上生效** ⇒ ⇒ 别的闸的自检坏没坏，CI 看不到。
- **债清单是手工维护的** ⇒ ⇒ 它自己也会过期 ⇒ ⇒ 「过期要销账」那条判据就是
  它的自检。
