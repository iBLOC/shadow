### 「位置型指针」是什么

账本里写「承**上一条**」「承**用户那句**」—— 指的是**位置**不是**编号**。
⇒ ⇒ 账本是只追加的 ⇒ ⇒ 插入/删除一条就指错 ⇒ ⇒ 用户原话已经不在文件里 ⇒ ⇒
**等于来源凭空**（论文说的那个 provenance failure：*a memory that keeps a stale conclusion
but drops its source becomes confidently uncorrectable, strictly worse than empty memory*）。

### 悬空指针的真实数字是 0

第一版量出「父仓 82 条悬空指针」—— **那是测量假象**：正则只认 `**Updated**:` 一种写法，
而父仓另有 104 条 `**Updated:**` 没被当成条目 ⇒ ⇒ 符号域缩水 ⇒ ⇒ 悬空指针被假绿。
⇒ ⇒ 修完是 **0**。教训：**量「悬空」之前先量「总数」，两者口径必须一致**。

| 规则 | 守什么 |
|---|---|
| R1 | 新条目（cutoff `2026-11-05` 之后）**必须带六字段信封**：`epoch` / `authority` / `scope` / `source` / `status` / `supersedes` |
| R2 | 信封的**值**要合法（epoch 是日期、authority/scope/status 在允许集合里） |

| R6 | 仓里有**未登记的状态面** ⇒ ⇒ 红 |
| R7 | **跨面同名**标记的引用**没有限定词** ⇒ ⇒ 读者分不清指的是哪一条 |

退出码：**0** 绿 / **1** 红 / **2** 源没读全（「没红」不等于「没问题」）。

### 信封长什么样

```markdown
> 信封：epoch=2026-11-05 | authority=user | scope=project | source=arXiv:2606.30306 §9.6 ＋ 本轮实测 | status=active | supersedes=none
```

- `epoch` —— 授权版本（日期或 `vN`）
- `authority` —— `user` / `measured` / `paper` / `inherited` / `runtime`
- `scope` —— `project` / `agent` / `user` / `session`
- `source` —— 来源（哪次会话 / 哪条观测 / 哪篇论文 / 哪次实测）
- `status` —— `active` / `superseded` / `retired`
- `supersedes` —— 被谁取代（`none` 或一个能解析的带圈编号）

## 四、两条后补的规则（同伴会话并行写入时暴露的）

仓里同时有多个会话在写账本 ⇒ ⇒ 于是补了**两条与「引用唯一性」有关的**规则
（它们**不是**论文里写的，是实测撞出来的）：

### R4 标记占用 —— 一个标记被两条条目占用 ⇒ ⇒ 引用是歧义的

| 面 | 实测 |
|---|---|
| 父仓账本 | **5** 个标记被两条占用（㋱ / ㋰ / ㋛ / ㋕ / ㊻） |
| 移动端账本 | **1** 个（㊸） |

⚠️ **这类失败比悬空更隐蔽** —— 悬空会红，歧义**不会**：
「承㋱」能解析，但解析出**两条** ⇒ ⇒ 读者拿到的是「某一条」，而它是**两条**。

⇒ ⇒ **两档分开**：含 cutoff 之后新条目的撞号 ⇒ ⇒ **新增即错，直接红**；
纯存量的撞号 ⇒ ⇒ 走债务清单（改号会打断已有引用 ⇒ ⇒ 只能慢慢还）。

### R7 跨面歧义引用 —— 同名标记 ＋ 没有限定词

移动端账本有 **46 个标记与父仓同名**（㋰…㋓ 等）⇒ ⇒ 于是「承㋤」**在本面与父仓各有一条**
⇒ ⇒ 不带限定词就分不清指的是哪一条 ⇒ ⇒ 实测 **25 处**。

判据认这几个限定词：`父仓` / `跨仓` / `主仓` / `本仓` / `另一面` / `对面`。

### 顺带发现的第四类债：记忆层引用了账本的编号

一条记忆（`Flutter 真机集成测试：退出码会撒谎`）里写「承㋱」⇒ ⇒ 但**记忆层没有带圈编号体系**
⇒ ⇒ 这个符号在本面解析不到 ⇒ ⇒ 它是**从账本那边抄过来的编号** ⇒ ⇒ 读者无法定位。

⇒ ⇒ 这提醒一件事：**编号体系本身也是状态** ⇒ ⇒ 一个面引入编号，就必须承担它的唯一性。

## 七、按**写入器自己的来源形状**判（2026-11-05 追加）

这一节是给**撤销通道**那条线补的，源于一次真机撞墙。

**撞墙的事实**：运行时的记忆工具对 user 面**只支持 read/search/append**
（user:edit 与 user:write 均 INVALID_OPERATION）⇒ ⇒ 它**不会**给用户偏好
生成六字段信封 ⇒ ⇒ 于是本闸的 R1「新条目必须带信封」在这个面上
**按默认写法根本做不到** ⇒ ⇒ 一条做不到的规则，就是一条永远红的规则。

**修法（不是放松，是换形状）**：

| 面 | 写入器 | 来源凭据 | 判据 |
|---|---|---|---|
| project/desktop/mobile-ledger | 人/agent 手写 | 六字段信封里的 source | 必须带信封 |
| agent-memory / user-memory | 运行时的记忆工具 | `<!-- mem-append-reason: … -->` 注释（**机器生成、不会忘**） | **信封 或 runtime 注释**，两者都没有才红 |

⚠️ 这个改动**不是全局放松**：面清单里没声明 `runtimeProvenance` 的面
（三个仓内账本）**仍然硬要信封**（自检里有对应的孪生用例钉住）。

⚠️ 而且 runtime 注释其实是**更强**的来源保证：它是机器生成的，
不像手写信封那样会忘。

**本节同时更新第六节的「仍然欠着」**：

- 第 5 条「用户偏好没有撤销通道」⇒ ⇒ **已还**（见 docs/superpowers/architecture/2026-11-05-preference-revocation.md）；
- 第 9 条「本轮没提交」⇒ ⇒ **已提交**（`421f338`）；
- 新欠：① 运行时**不支持** user 面的 edit/write ⇒ ⇒ 原条目永远留在文件里
  （要真正物理删除需产品侧给记忆子系统加 delete/update）；
  ② agent 记忆层的**悬空引用**计数会单调增长（1 → 4）⇒ ⇒ 真解是禁止在记忆层用带圈引用。


## 八、闸自己的**假绿**：一个没闭合的围栏，把 28 条记忆吞掉了

**撞墙的事实**（2026-11-05 实测）：闸报「零违规」，而它**自己漏看了 28 条记忆**
（条目数 150 ⇒ 真实 178）。

**根因**：旧判据把「**行首**有 ``` 」当作围栏标记 ⇒ ⇒ 而记忆层第 2164 行是一句
**以 ``` 开头的散文**（「``` ⇒ ⇒ 没有结论 ⇒ 判失败」）⇒ ⇒ 它被当成了**围栏开头**
⇒ ⇒ 后面所有围栏的**奇偶性整体错位** ⇒ ⇒ 第 2208/2215 那对本来配对的围栏
被算成「没闭合」⇒ ⇒ **221 行连同 7 条无日期记忆被整段吞掉**。

**三重教训**：

1. 「认形状不认关键词」的**对面**是：**认形状时，形状必须定义得够严** ——
   「行首有 ```」太松 ⇒ ⇒ 改成「**整行只有围栏标记**才算围栏」；
2. **闸的覆盖面本身要被验证** —— 这次是**条目总数**从 150 变 178 暴露的 ⇒ ⇒
   与「量异常之前先量总数」同源：**分母错了，异常数全是假的**；
3. **静默吞内容是最坏的失败模式** —— 少算条目、少算悬空指针，闸却报「零违规」
   ⇒ ⇒ 现在加了 **R8**：围栏不配对 ⇒ ⇒ 直接红，并报出「第几行开的围栏、
   后面吞了几行、第一条被吞掉的是谁」。

## 九、带圈指针：在**没有编号体系**的面里，它**永远解析不到**（R9）

**事实**：记忆层与用户偏好面**都没有带圈编号体系** ⇒ ⇒ 那些面的条目里若出现
「承㋱」这种指针 ⇒ ⇒ 它**永远解析不到** ⇒ ⇒ 读者无法定位。

**为什么单列一档而不是走债**：这一档不是「可能指错」，是**形状本身就不该出现**
⇒ ⇒ 直接红（R9），不走债务清单。

**一个自指的坑**（2026-11-05 实测）：记忆层的悬空引用从 1 涨到 4，涨的那 3 处
**全在两条新写的教训里** —— 因为**写「指针卫生」这类教训时，会拿真的带圈符号
当反面例子** ⇒ ⇒ 于是每写一条教训就多几处悬空 ⇒ ⇒ 计数**单调增长** ⇒ ⇒
靠「登记」永远堵不住（登记只是把 1 改成 4、4 改成 7）。

**修法（两处一起）**：

1. **判据**：R9 ⇒ ⇒ 没有编号体系的面里不许出现「承+带圈符号」⇒ ⇒ 写反面例子
   要用**带圈范围之外**的占位符（例如 承〈某符号〉）；
2. **内容**：把记忆层那 4 处真符号改成占位符（用记忆工具的 edit 就地改）⇒ ⇒
   悬空引用 **4 → 0** ⇒ ⇒ **销账**（从债务清单里移除那条登记）。

**顺带修的**：那 4 条新记忆的写入调用**没传 reason** ⇒ ⇒ 运行时没盖
`mem-append-reason` 注释 ⇒ ⇒ 它们既没有信封也没有来源 ⇒ ⇒ R1 红 ⇒ ⇒
给它们补了信封（本轮与同伴会话各写了其中两条）。⇒ ⇒ 顺带把 agent 记忆层也标成
`runtimeProvenance`（**它与用户偏好面是同一个写入器**）⇒ ⇒ 规则形状一致。

**读数**：状态面闸自检 **31/31**（新增 6 条：R8 正向 / R8 连带 / 围栏配对孪生 /
R9 正向 / 占位符孪生 / 未声明面孪生）；主检查本地与 CI 模式**均零违规**；
撤销通道闸 21/21 且零违规。
