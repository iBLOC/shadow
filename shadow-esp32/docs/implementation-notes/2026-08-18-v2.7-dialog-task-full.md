## v2.7 dialog_task 完整流程

```
1. k_sem_take(&shadow_net_wifi_up)             等 net_task 完成
2. uuid_v4_string(session_id)                  生成 session ID
3. random_ice_credentials(ufrag, pwd)          ICE 凭据
4. build_sdp_offer(sdp, ufrag, pwd)            SDP offer (含 placeholder fingerprint)
5. build_offer_json(offer, session_id, sdp)    SignalingMessage::Offer JSON
6. shadow_ws_connect(cortex)                   WebSocket signaling
7. shadow_ws_send_text(offer)                  发 SDP offer
8. shadow_ws_recv_text(buf)                    收 Answer + Connected
9. parse SDP answer → remote_ip:remote_port    解析 temporal lobe 的 UDP 端点
10. shadow_dtls_set_psk()                      配置 PSK (demo key)
11. shadow_dtls_handshake_udp(remote_ip, port) 真 DTLS handshake → 30-byte SRTP key
12. zsock_socket + zsock_inet_pton             打开 UDP socket
13. STUN Binding Request → temporal lobe       ICE-lite 连通性检查
14. shadow_audio_pipeline_start()              启动音频管线
15. shadow_srtp_open(srtp_master)              用真 DTLS-derived key 创建 SRTP session
16. shadow_opus_encoder_open()                 创建 opus encoder
17. === media loop ===
    读 mic PCM → opus_encode → srtp_protect → sendto(temporal)
    recvfrom → STUN? 响应 / SRTP? decode+play / data channel? dispatch MCP
    k_sleep(10ms)
18. 按 dialog_running atomic 停止 → 清理资源
```

## 关键设计选择

### DTLS PSK 而不是证书

```
static const uint8_t dtls_psk[] = {
    0x73, 0x68, 0x61, 0x64, 0x6f, 0x77, 0x2d, 0x70,  /* "shadow-p" */
    0x73, 0x6b, 0x2d, 0x32, 0x30, 0x32, 0x36, 0x00,  /* "sk-2026\0" */
};
```

mbedtls DTLS PSK 不需要证书,握手更快(3 RTT vs 5+ RTT),对 ESP32 这种资源受限设备更合适。生产环境 PSK 从 NVS provisioned by BLE.

### 真 SRTP key

```c
uint8_t srtp_master[30];
shadow_dtls_handshake_udp(remote_ip, remote_port, srtp_master, 30);
shadow_srtp_open(srtp_master, 30);
```

v2.7 之后 SRTP 用的是真 DTLS-exported key,不再是 v2.2.2 的 static fallback。如果 DTLS 失败,仍 fallback 到 static key 让 smoke test 可用。

### ICE-lite STUN

```c
uint8_t stun_req[20]; /* magic cookie + tx_id */
zsock_sendto(media_fd, stun_req, 20, 0, &remote_addr, ...);
```

只是一个 STUN Binding Request — temporal lobe 会回 Binding Success(包含 mapped address)。这个 STUN 交换是 ICE 连通性检查的第一步。后续再做 trickle-ICE (增量 push + candidate 存储)。

### Media loop 10ms tick

```c
while (atomic_get(&dialog_running)) {
    /* send mic → opus → SRTP → UDP */
    /* recv UDP → STUN/SRTP/MCP dispatch */
    k_sleep(K_MSEC(10));
}
```

10ms 一次 send/receive 循环。实际使用 opus 60ms 帧长 → 每 6 次循环读一个 opus frame → 发一次 SRTP。接收循环每次 poll 一个 UDP datagram。

## 已知边界

1. **PSK 是硬编码 demo key** — 生产需 NVS provisioned by BLE
2. **STUN 只发了 Binding Request,没等响应** — 响应处理留在 recvfrom dispatch
3. **remote_ip:remote_port 解析简单** — `c=IN IP4 <ip>` 和 `m=audio <port>` 解析,不处理 ICE candidate
4. **没做 ICE 连通性检查 loop** — 只是发一个 STUN request,没等 Binding Success
5. **DTLS handshake 失败时 fallback 到 static key** — 用于 smoke test,不做 DTLS SRTP
6. **no receive timeout** — 如果 temporal lobe 不发包,dialog_task 会一直 poll
