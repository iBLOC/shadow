## 数字人直播 v2.5 完整开机流

```
1. shadow-esp32 上电
   - settings_subsys_init() 读 NVS,有 SSID → CONNECTED,有 PSK → 直接进 Wi-Fi
   - 无 SSID → 启动 BLE peripheral "shadow-esp32 setup"

2. Android 配网 app
   - BLE scan → "shadow-esp32 setup"
   - GATT discover → primary service 12345678-0001-...
   - write SSID → char 12345678-0002-...   (write_ssid cb)
       settings_save("shadow/wifi/ssid", ...)  → NVS
       atomic_set status = CONNECTING
   - write PSK  → char 12345678-0003-...   (write_psk cb)
       settings_save("shadow/wifi/psk", ...)   → NVS
   - read status → char 12345678-0004-...   (read_status cb)
       "connecting" 或后续 "connected"

3. shadow-esp32 net_task
   - wifi_connect_loaded_creds() 读 settings,connect 到 Wi-Fi
   - 成功 → status = CONNECTED
   - 失败 → status = FAILED,Android app retry

4. shadow-esp32 上线
   - mDNS _shadow._tcp 广播
   - cortex/temporal 通过 WebRTC 连接
   - 数字人直播流
```

## BLE GATT UUID 表

| 类型 | UUID (custom 128-bit) | 用途 |
|---|---|---|
| Service | 12345678-0001-... | Primary "shadow provisioning" |
| Char SSID | 12345678-0002-... | write(UTF-8, ≤32B) |
| Char PSK | 12345678-0003-... | write(UTF-8, ≤63B) |
| Char Status | 12345678-0004-... | read("idle"\|"connecting"\|"connected"\|"failed") |

Android app 端硬编码这些 UUID 即可。

## 已知边界

1. **v2.5 SSID/PSK 走 BLE cleartext** — 配网场景下短暂出现 BLE 链路是安全的(有人必须物理接近);v2.6 配 BLE bonding 加密
2. **2.4 GHz 共存** — BLE + Wi-Fi 共享 2.4 GHz,会有 5-10% 性能损失;5 GHz Wi-Fi + BLE 5.x 解决
3. **NVS 写入延迟** — settings_save_one 是 sync,configurations 写入 ~5-10 ms;配网 1-2 s 总体验
4. **LED 不指示 provision 状态** — v2.5 只在 console log;v2.6 加 LED 闪烁指示
5. **Android 端 app 不在 shadow-esp32 仓库** — 用户自己写或用 NRF Connect 等通用 app
6. **Provisioning 仅 v2.5** — 一旦配网成功,关闭 BLE peripheral;重新触发是长按 BOOT 按钮(v2.6 留)

## 验证

```bash
west build -b esp32s3_devkitc app
west flash

# 串口应见:
# [shadow_main] shadow-esp32 booting (Zephyr 3.x.x)
# [shadow_provision] provision: loaded creds from settings, ssid=mywifi
# 或
# [shadow_provision] provision: stored creds from settings, ssid=mywifi

# BLE 配网演示
# 在 Android 上用 NRF Connect:
# 1. Scan → "shadow-esp32 setup"
# 2. Connect
# 3. Service 12345678-0001-...
# 4. char 0002 → write "MyWiFi" (SSID)
# 5. char 0003 → write "MyPassword" (PSK)
# 6. char 0004 → read → "connecting" → 几秒后 "connected"

# shadow-esp32 串口:
# [shadow_provision] prov: write_ssid 6 bytes
# [shadow_provision] provision: stored ssid=MyWiFi psk_len=11
# [shadow_provision] prov: write_psk 11 bytes
# [net_task] wifi_connect_loaded_creds: ssid=MyWiFi psk_len=11
# [net_task] shadow_net_wifi_up signaled
```
