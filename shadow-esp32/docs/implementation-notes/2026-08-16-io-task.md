# shadow-esp32 io_task v1 实施记录 (2026-08-16, ADR-0002 v2 §后续动作 #6)

## 本次提交改了什么

把占位心跳 `io_task.c`(38 行)替换为**真实 MCP server + 工具注册表**:
- 完整 JSON-RPC 2.0 dispatcher(hand-rolled,无 JSON 库依赖)
- 5 个 v1 工具,其中 1 个真功能(`self.system.reboot` 调 `sys_reboot`)、2 个日志存根(GPIO/light)、1 个 placeholder(light set_brightness)
- 工具注册表(idempotent by name)
- `tools/list` 序列化返回 MCP 标准 schema
- 公共 API header `app/src/include/shadow_esp32/io_tools.h`

## io_task 设计

### 公共 API (`io_tools.h`)

```c
typedef int (*shadow_tool_fn)(const char *args_json,
                              char *result, size_t result_cap);

struct shadow_tool {
    const char *name;            // "self.light.set_rgb"
    const char *description;
    const char *input_schema_json;  // {"type":"object",...}
    bool user_only;
    shadow_tool_fn invoke;
};

int shadow_io_register_tool(const struct shadow_tool *tool);
size_t shadow_io_tool_count(void);
size_t shadow_io_list_tools_json(char *buf, size_t cap);
size_t shadow_io_invoke_mcp(const char *request, char *response, size_t cap);
```

### JSON-RPC dispatcher 支持的 methods

| Method | 行为 |
|---|---|
| `initialize` | 返回 `{"protocolVersion":"2024-11-05","capabilities":{"tools":{}},"serverInfo":{"name":"shadow-esp32","version":"0.0.1"}}` |
| `tools/list` | 返回 `{"tools":[{...}]}` 包含所有已注册工具 |
| `tools/call` | 按 `params.name` 找工具,调 `params.arguments` 作为 JSON 字符串;成功包成 `{"result":...}`;失败返回 JSON-RPC error |
| 其他 | 返回 `method not found` (code -32601) |

### v1 工具集

| 名称 | user_only | v1 行为 | 后续 commit |
|---|---|---|---|
| `self.io.gpio_set` | false | 解析 `{"pin":N,"value":0\|1}` → log + return ok | 接 Zephyr `gpio_dt_spec` 写实际 GPIO |
| `self.io.gpio_get` | false | 解析 `{"pin":N}` → log + return `{"pin":N,"value":0}` | 接 `gpio_pin_get_raw` |
| `self.light.set_rgb` | false | 解析 `{"r":N,"g":N,"b":N}` → log + return ok | 接 LED strip / RGB GPIO |
| `self.light.set_brightness` | false | 解析 `{"level":N}` → log + return ok | PWM duty cycle |
| `self.system.reboot` | **true** | 解析(忽略 args)→ 200ms 后 `sys_reboot(SYS_REBOOT_WARM)` | 实际可触发 |

## 与其他任务的接线

```
+---------------------+        +-----------------------+
|   dialog_task v2    |        |     io_task v1        |
| (WebRTC data ch.)   |        | (MCP server)          |
|                     |        |                       |
| on_data_channel     |        | g_tools[]             |
|   message →         | -----> | shadow_io_invoke_mcp()|
|   shadow_io_invoke  |        | → find by name        |
|   _mcp              |        | → call tool handler   |
|                     |        | → JSON-RPC reply      |
+---------------------+        +-----------------------+
```

v1 阶段 `dialog_task` 没有 data channel,所以 `shadow_io_invoke_mcp()` 只是 v1 子任务暴露的**本地 API**;data channel 集成在 `dialog_task` v2 阶段做。

## JSON 解析策略(v1)

**Hand-rolled,无外部库**:
- `json_get_string(key)` — `strstr` 找 `"key":"`,截到下一个 `"`;够用因为所有 JSON 都是 flat key-value
- `json_get_int(key)` — `strstr` + `strtol`
- `json_get_object(key)` — 找 `"key":{` 后用括号深度计数(支持嵌套)

**不**支持:
- Array(本次不需要)
- Unicode 转义(`\uXXXX`)— ESP32 不输出中文到本设备工具 args
- 数字带前导 0 / 科学计数法

v1 接受 trade-off(无 JSON 库)换取更小 footprint;v2 若需要 array/复杂 schema 引入 `cJSON` 或 `Jansson` 即可。

## 关键 Kconfig / prj.conf

无新增 Kconfig(io_task 不需要 network)。后续 GPIO 真实接线需要 devicetree overlay:

```devicetree
/* app/boards/esp32s3_devkitc.overlay  (follow-up commit) */
&pinctrl {
    shadow_io_default: shadow_io_default {
        group1 {
            psels: <GPIO48>;
        };
    };
};

gpio: &gpio0 {
    shadow_led: shadow_led {
        compatible = "gpio-leds";
        gpios = <&gpio0 48 GPIO_ACTIVE_HIGH>;
        label = "shadow_led";
    };
};
```

## 已知边界

1. **本机无 Zephyr SDK** — 验证只能在 devcontainer / CI 跑 `west build`
2. **所有工具 v1 实际不驱动硬件** — 等 devicetree overlay + GPIO 接线就位
3. **JSON 解析能力有限** — 不支持 array / 复杂 schema(后续 cJSON 替换)
4. **`self.system.reboot` 是真实危险的** — 通过 MCP 调它就真重启;`user_only=true` 标记需要 cortex 在 invoke 前校验 user flag(否则 LLM 误调就重)
5. **没有并发保护** — `g_tools[]` 数组在 io_task 启动时注册,之后只读;如果未来需要动态注册/注销需要 mutex
