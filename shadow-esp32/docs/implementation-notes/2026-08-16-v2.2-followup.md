## 设计取舍

### WS2812:用 Zephyr 标准 `<zephyr/drivers/led_strip.h>` API

- 不写自定义 bit-bang 驱动(Zephyr mainline 有 `led_strip` API 适配各种 backend)
- v2.2 工具逻辑:有 `led_strip` devicetree 节点 → 走 RGB;否则走 binary fallback(GPIO 高低)
- 这意味着 bare devkitc 没 WS2812 也跑得通(smoke test 用 binary);接 WS2812 后自动 RGB

### I²C sensor:`<zephyr/drivers/i2c.h>` + `i2c_reg_read_byte`

- 单字节 register read(够 90% smoke 用)
- 真实 sensor 接入 devicetree 后(`shadow_sensor@0x68`)→ I²C 读从 wire 上 0x68 reg N 拿 1 byte
- 多字节 / burst read 留 v2.3

### DTLS 真 key export:folding hash

- v1 placeholder 是简单 `psk[i % len] + i`,v1.5 改用 XOR folding 接近 PRF 性质
- 真 `mbedtls_ssl_export_keying_material` 留 v2.2.1(一行的改动)
- 输出 30 bytes 跟 v1 完全 bit-compatible(基于同一 PSK 输出一致)

### OTA 签名:`imgtool sign` wrapper

- 不用自创格式,直接调 `imgtool`(Espressif / MCUboot 官方)
- 脚本输出 `zephyr.signed.bin` 给 `mcumgr image upload`
- 签名 key 占位在 `tools/ota-signing-key.pem`(commit 时不签,首次 OTA 时由 developer 本地生成)

### usrsctp:west.yml 占位,实际集成留 v2.2.1

- west.yml 已加 `libusrsctp: master`,`west update` 会拉源码
- `sctp_agent.c` 现在做 byte-level framing;v2.2.1 把 usrsctp 关联起来
- 不在本次 commit 集成是为了避免引入大块外源构建时间

## 已知边界

1. **DTLS 真 key export** 仍待 v2.2.1 — folding-hash 接近但不是真正的 TLS exporter
2. **WS2812 需要 devicetree 节点** — bare devkitc 不带,加 `&ws2812_strip` 节点后才走 RGB 路径
3. **I²C sensor 真实接入** 需要具体 sensor (BME280 / MPU6050 等) 接 I²C0 (SDA=GPIO8 / SCL=GPIO9)
4. **usrsctp 真集成** 留 v2.2.1 — west.yml 已加项目,实际 CMake wrapper 后续 commit
5. **OTA 签名 key** 留 developer 在首次 OTA 时本地 `imgtool keygen`,不入 git
