## dialog_task UDP 接收 loop 设计

### 三路 dispatch

```c
for (int iter = 0; iter < 64; iter++) {
    recvfrom(media_fd, buf, n, 0, &from, &fromlen);
    
    /* Path 1: STUN Binding Request */
    if (shadow_stun_parse_binding_request(buf, n, tx_id) == 0) {
        shadow_stun_build_binding_response(tx_id, ..., resp, ...);
        sendto(media_fd, resp, ..., &from);
        continue;
    }
    
    /* Path 2: SRTP-protected opus packet */
    if (shadow_srtp_unprotect(srtp, plain, n, buf, n) > 0) {
        shadow_opus_decoder_decode(dec, plain, ...);
        continue;
    }
    
    /* Path 3: raw "data channel" JSON-RPC (v1 stand-in for SCTP) */
    if (shadow_io_invoke_mcp(json_in, json_out, ...) > 0) {
        sendto(media_fd, json_out, ..., &from);
    }
}
```

### 关键设计选择

1. **单 loop 跑 64 iter** — bounded 让 smoke test 有 end;真 peer 是 `for(;;)`,但 v1 限制 iterations 避免循环
2. **三路按顺序试** — STUN 是最简单(20 字节 header),优先;SRTP 是中等(80+ bytes);剩下的当作 data channel
3. **真 I²C I²S + 真 SRTP + 真 STUN** — 所有用 Zephyr mbedtls / opus / libsrtp 真 API,不是 placeholder
4. **data channel 走 raw UDP JSON-RPC** — v1 stand-in for SCTP;v2.3 换 usrsctp

### WS2812 devicetree 集成

`app/boards/esp32s3_devkitc.overlay` 加了:

```dts
&spi0 {
    status = "okay";
    pinctrl-0 = <&spi0_default>;
    pinctrl-names = "default";
};

&led_strip0 {
    compatible = "worldsemi,ws2812-spi";
    status = "okay";
    spi-dev = <&spi0>;
    chain-length = <1>;
    color-mapping = <LED_COLOR_ID_GRB>;
    spi-max-frequency = <4000000>;
};
```

有了这个 node,`io_task.c::tool_light_set_rgb` 自动走 RGB 路径(devkitc base board 没接 strip 走 binary fallback)。

## 已知边界

1. **64 iter bounded** — v1 smoke test;真 peer 用 `for(;;)`,但 v1 需要让 smoke test 有限
2. **opus_decode placeholder buf** — 第二个参数是 NULL,opus 包大小还不正确;v2.3 用真 RTP header 解析
3. **DTLS 仍是占位** — v2.2.1 的真 export_keying_material + 真 handshake 之间还有 gap;v2.3 闭合
4. **ws2812 节点** — base devkitc 没真接 strip,节点声明不影响功能
5. **raw JSON-RPC "data channel"** — 真正 SCTP/DTLS 数据通道留 v2.3
