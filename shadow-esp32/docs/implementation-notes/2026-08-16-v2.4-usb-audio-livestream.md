## 数字人直播 PoC 架构

```
┌─────────────────┐  USB-C  ┌──────────────────┐
│  Phone (Android)│ ◀──────▶│  shadow-esp32    │
│                  │         │  (ESP32-S3)       │
│ ┌──────────────┐ │         │                  │
│ │ App:        │ │         │ ┌──────────────┐  │
│ │ - subscribe │ │ USB     │ │  UAC1 device │  │
│ │   live-stream│ Audio   │ │  AS OUT EP    │  │
│ │ - OCR danmaku│ OUT 16kHz│ │  callback     │  │
│ │ - TTS / play │ mono 16b│ │     ↓         │  │
│ │              │ ───────▶ │ │  PCM out      │  │
│ │ AudioTrack → │         │ │  → I²S TX     │  │
│ │ USB device   │         │ │  → MAX98357A   │  │
│ └──────────────┘ │         │ │  → speaker    │  │
│                  │         │ └──────────────┘  │
│ (optional:       │         │                  │
│  send danmaku    │ ──┐     │  self.event.     │
│  via data channel)│  └────▶│   danmaku tool   │
│  (JSON-RPC)     │         │   (MCP dispatcher)│
│                  │         │   → log + LED    │
└─────────────────┘         └──────────────────┘
```

### 三条路径

1. **USB Audio OUT**(主路):phone 推流 PCM → shadow-esp32 → I²S → 音箱
2. **raw JSON-RPC "data channel"**(mcp dispatcher) 现有路径,OCR 文本走这里
3. **MCP `self.event.danmaku` tool**(本次新加):v2.4 简单 log + LED pulse;v2.5 接 cortex 把 danmaku 当 user-utterance

## 关键设计取舍

### USB Audio OUT 而非 IN

按 USB Audio 术语,**OUT 是 device→host**。Phone 播放数字人语音 → USB 送 PCM 到 shadow-esp32 = **device 接收** = **IN endpoint**(从 host 角度)。

但 Zephyr UAC1 driver 命名里,`data_received_cb` 对应"device 收到 host 数据"的方向,**device 端 OUT endpoint 的 OUT 是从 host 写入 device**。

为避免混淆,代码注释里说明:"shadow-esp32 exposes a single AS interface with 16 kHz / 16-bit / mono PCM OUT endpoint. The phone ... writes its synthesized voice frames into it."

### 不创建新 task(USB device task)

`shadow_usb_audio_run()` 当前是空 loop;Zephyr 的 USB device stack 自动管理 isochronous OUT callback thread,`data_received_cb` 由 UAC1 driver 调度。dialog_task / led_task 都不需要改(USB OUT 帧直接进 audio_pipeline 写 I²S TX)。

### 直播 latency 分析(更新 v2.4 评估)

| 段 | 延迟 |
|---|---|
| Phone 端:订阅直播流 + 解码 | ~100-500 ms(网络) |
| Phone → USB Audio → shadow-esp32 | 1-10 ms |
| **合计** | **~110-510 ms** |

单向播报完全可接受;数字人直播是单向,所以"数字人说话 → 直播间看到听到"链条 ~250ms median。

## 已知边界

1. **USB FS(12 Mbps)** — 16 kHz/16-bit/mono = 256 kbps,**充裕**;48 kHz/24-bit/stereo 才会到 2.3 Mbps
2. **OTG 5V 协商** — phone 通常给 500mA,ESP32-S3 启动 240mA,I²S 启动 spike 可能触发 phone 限流;实测时建议用带电源的 hub
3. **iOS** — Apple 严格 USB Audio device 政策,Lightning-to-USB 适配器限制多,**demo 限定 Android**
4. **Wi-Fi 2.4 GHz ↔ USB 2.0** 共享 2.4 GHz 频段,可能干扰;5 GHz Wi-Fi 解决
5. **`self.event.danmaku` v2.4** — 只 log + LED pulse;v2.5 接 cortex A2A
6. **OTG ID pull-up** — Zephyr dwc2 driver 内部处理,但 devkitc base board 有时需要手动确认
