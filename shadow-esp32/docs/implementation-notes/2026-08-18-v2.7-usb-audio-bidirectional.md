## 双向 USB Audio 设计

```
┌──────────────────────────────────────────────────────────┐
│                    shadow-esp32                            │
│                                                          │
│  ┌──────────────┐   USB Audio OUT   ┌──────────────┐    │
│  │  I²S PDM RX │ ─── mic capture ──▶│  I²S TX      │    │
│  │  (GPIO15/16)│   (k_msgq)         │ (GPIO17/9)  │    │
│  └──────────────┘                   └──────┬───────┘    │
│         │                                  │              │
│         ▼ (USB Audio IN callback)          ▼              │
│  ┌──────────────┐                   ┌──────────────┐    │
│  │ phone ASR    │                   │ speaker      │    │
│  │ (via host)   │                   │              │    │
│  └──────────────┘                   └──────────────┘    │
└──────────────────────────────────────────────────────────┘
```

## USB Audio 类描述符设计

Zephyr 的 `usb_audio` class driver 基于 devicetree 的 `compatible = "usb-audio-class"` 节点自动生成 UAC1 描述符。我们只需要:
1. devicetree 配置 UAC1 streaming interfaces (OUT + IN)
2. Kconfig 启用双向
3. 在 C 代码里 `uac1_config` 注册两个 callback

v2.7 已完成全部 3 步。

## 双向 PCM 流路径

### OUT (手机→设备播放,已有)
```
phone TTS → AudioManager → USB Audio OUT endpoint
  ↓ uac1_config.data_received_cb
shadow_audio_pipeline_write_pcm()
  ↓ I²S TX DMA
  ↓ MAX98357A → speaker
```

### IN (设备→手机麦克风, v2.7 新增)
```
mic (INMP441) → I²S PDM RX capture
  ↓ shadow_audio_pipeline_read_pcm() (k_msgq ring)
  ↓ uac1_config.data_request_cb
USB Audio IN endpoint → host → phone ASR
```

`in_requested_cb` 是 host 主动 poll 我们:
- Zephyr UAC1 驱动在 host 打开 IN stream 后调 `in_requested_cb`
- 我们从 `shadow_audio_pipeline_read_pcm()` 拉 16kHz/16bit/mono PCM
- 如果没 mic (bare devkitc) 用 silence fill,host stream 不会 stall

## 已知边界

1. **USB FS 带宽** — 16kHz/16bit/mono OUT = 256 kbps + IN = 256 kbps = 512 kbps 合计,USB FS 12 Mbps 充裕
2. **host 主动 poll 模式** — 当前 `in_requested_cb` 是同步阻塞;i2s_read 在这回调里跑,如果 i2s_read 阻塞会 stall host。生产版本用后台 capture thread + ring buffer (audio_pipeline.c 的 v1.5 结构),改为定时器驱动
3. **未实现 `shadow_usb_audio_send_pcm()` 的 push 模式** — v2.7 只有 host 主动 poll,device 被动提供。如果 host 没开 IN stream,device 数据不被消费(会 ring buffer 溢出)
4. **没加 USB streaming mutes** — host 期望 mute/unmute 控制;需加 USB Audio class mute handler
5. **iOS 不开放 USB Audio Class device mode** — 仅 Android + Linux + macOS

## 验证

```bash
west build -b esp32s3_devkitc app
# 串口
# [shadow_main] shadow-esp32 booting (Zephyr 3.x.x)
# [shadow_usb_audio] uac1 device registered (16 kHz / 16-bit / mono OUT + IN)
# [shadow_main] shadow-esp32 booted; main thread idle

# 插入 Android phone:
# adb shell dumpsys audio
# → "USB Audio Device" 出现 IN + OUT endpoints

# voice assistant mode:
# 对着 shadow-esp32 mic 说话 → phone ASR → TTS → USB OUT → shadow-esp32 → speaker
# (shadow-esp32 mic 充当 phone USB 麦克风)

# livestream mode:
# phone TTS text → USB OUT → shadow-esp32 → speaker
# shadow-esp32 mic 数据被 host 消费但不播放(not required for live-stream)
```
